# Media Factory 交互升级设计方案

**日期：** 2026-09-02
**状态：** 已 review 确认

## 目标

在现有 CLI + Web 服务基础上，升级为可实时观察"内容生产流水线"的体验：任务化、流式展示中间产物、播客人物/人数可选、字幕优化、UI 美化 + 浅色主题。

---

## 一、任务模型（历史列表 / 新建任务）

**核心变化：任务从"目录"升级为"有状态的对象"。**

每个任务目录 `output/<id>/` 下新增 `task.json` 元数据：

```json
{
  "id": "20260831-143000",
  "status": "running",          // pending / running / done / failed
  "current_step": "podcast",    // rewrite / image / podcast / video
  "steps": {
    "rewrite": "done",
    "image":   "done",
    "podcast": "running",
    "video":   "pending"
  },
  "created_at": "...",
  "updated_at": "...",
  "config": { "podcast_people": 2 }
}
```

**前端：**
- 「**＋ 新建任务**」按钮 → 清空工作区，进入新任务输入态
- 任务列表每项：任务 id、状态灯（绿=完成 / 蓝=运行中 / 红=失败 / 灰=待处理）、当前步骤、产物数量
- 点击历史任务 → 查看完整中间产物，音频/视频可播放

## 二、流式执行与中间产物（核心需求）

### 2.1 架构变化：同步阻塞 → 后台执行 + SSE 推送

```
当前：POST /api/run → 阻塞 10 分钟 → 一次性返回全部结果
改为：POST /api/run → 立即返回 task_id（后台异步执行）
      GET /api/tasks/:id/events → SSE 长连接，实时推送事件
```

**后端事件模型**（`tokio::sync::broadcast` 广播）：

| 事件 | 触发时机 | 含义 |
|---|---|---|
| `step:{step}:running` | 某步开始 | 点亮流水线对应节点（呼吸闪烁） |
| `chunk:{step}:{delta}` | 改写/脚本流式输出 | 文本逐块追加（打字机效果） |
| `artifact:{step}:{name}:{url}` | 中间产物落盘 | 该步产物面板出现 |
| `step:{step}:done` | 某步完成 | 节点变绿/琥珀 |
| `progress:{step}:{percent}` | 视频 ffmpeg 编码 | 进度条 |
| `task:done` / `task:error` | 整体结束/失败 | 收尾状态 |

**中间产物"即产即现"的粒度：**
- **改写**：LLM token 级流式（`text_delta` / `stream=true`），前端打字机渲染
- **生图**：先"生成中…" → 图片一产出立即显示
- **播客**：轮次级进度（"第 3/12 轮对话合成中"）→ 音频产出后播放器出现；字幕 srt 产出即显示
- **视频**：ffmpeg 进度百分比 → 完成后视频播放器出现

### 2.2 前端交互设计

运行中的任务，工作区变成"生产线直播"视图：

```
┌──────────────────────────────────────────────┐
│ 任务 #20260831-143000        ● 运行中        │
│                                              │
│   改写 ──── 生图 ──── 播客 ──── 视频          │
│    ●✅      ●✅       ◐运行中    ○待定         │
│   (琥珀亮)  (琥珀亮)  (呼吸蓝)   (灰)          │
│                                              │
│ ┌─ 正在执行：播客（双人对话合成）──────────┐   │
│ │  第 3 / 12 轮 · 主持人 ↔ 嘉宾对话        │   │
│ │  ▓▓▓▓▓░░░░░░░░░  25%                     │   │
│ └──────────────────────────────────────────┘   │
│                                              │
│ 中间产物（实时滚动出现）                        │
│ ├─ 📝 改写文案 ✅  [打字机流式文本…]            │
│ ├─ 🖼 配图     ✅  [图片预览]                   │
│ ├─ 🎙 播客音频 ◐  [生成中…]                    │
│ └─ 🎬 视频     ○  [等待]                       │
└──────────────────────────────────────────────┘
```

**交互细节：**
1. **流水线节点**：灰=未开始 / 蓝呼吸=运行中 / 琥珀亮=完成 / 红=失败；连线随进度"流动"
2. **产物面板按产出顺序"生长"**：每完成一步，对应面板滑入，不等全部结束一次性刷新
3. **改写文案**：打字机逐字出现
4. **失败恢复**：某步失败 → 节点变红、错误信息展示，已完成产物保留；可"重试此步"
5. **任务完成**：流水线全部点亮，媒体可播放，提供"下载全部"

## 三、播客人物与人数

**配置扩展**（播客 provider 配置弹窗新增）：
- **人数**：下拉 1~2 人（默认双人对话）
- **人物/音色**：每人生成时从音色列表选（火山播客专属音色：黑猫侦探社咪仔 / 大医先生 / 刘飞 / 潇磊，以及 TTS 音色列表）
- 保存到 provider 的 `extra`：`speaker_count` + `speaker1` / `speaker2`

**调用时**：`speaker_info.speakers` 传入所选音色；人数 1 时传 1 个音色。

> ⚠️ 火山文档写"只能选择 2 发音人"。实现前需实测确认 1 人是否支持；若只支持 2 人，则 1 人选项禁用或隐藏。

## 四、字幕优化

1. **英文单词折行**：
   - `split_subtitle_text` 按**词边界**切分（英文空格/标点），不在单词中间硬切；中文仍按标点/字数
   - ASS `force_style` 加 `WrapStyle=0`（智能换行，不拆单词）
2. **字号调大**：11px → **13px**

- 重新走 frontend-design 技能做完整视觉重构

- 保留"生产线"签名元素，优化配色、间距、字体层级、动效（节点呼吸、产物滑入、打字机）

## 关键决策点（已确认）

1. **流式架构**：`POST /api/run` 改为"立即返回 task_id + 后台执行"，前端用 SSE 订阅事件
2. **流式粒度**：改写=token 级打字机，播客=轮次级进度，视频=百分比进度
3. **播客人数**：先按 1~2 人设计，实测前若只支持 2 人则禁用 1 人
4. **字幕字号**：11px → 13px
